# ODIN V2 — API Contract

**Version:** 1.0  
**Date:** 2026-10-22  
**Status:** Draft — defining minimal contract for parallel development

---

## 1. Entities & Identifiers

| Entity | ID Format | Description |
|--------|-----------|-------------|
| Conversation | `conv_<uuid>` | Chat session in Odin |
| Message | `msg_<uuid>` | Single message in a conversation |
| Knowledge Item | `knw_<uuid>` | Note, link, snippet, personal record |
| Run/Execution | `run_<uuid>` | Agent execution triggered from a conversation |
| Approval | `apr_<uuid>` | Pending approval request from Hermes |
| Session (Hermes) | `ses_<uuid>` | Hermes internal session ID (opaque to clients) |

All IDs are generated by the Odin backend (UUIDv4 prefixed).

## 2. HTTP Routes

### 2.1 Health & Auth

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/health` | No | Lightweight liveness probe |
| GET | `/api/system/status` | No | Full system status (gateway, DB, Hermes) |
| POST | `/api/auth/login` | No | Email/password → session token |
| POST | `/api/auth/logout` | Yes | Invalidate session |

### 2.2 Conversations

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/conversations` | Yes | List conversations (paginated) |
| POST | `/api/conversations` | Yes | Create new conversation |
| GET | `/api/conversations/{id}` | Yes | Get conversation metadata |
| GET | `/api/conversations/{id}/messages` | Yes | List messages (paginated) |
| DELETE | `/api/conversations/{id}` | Yes | Delete conversation |

### 2.3 Runs (Agent Executions)

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| POST | `/api/conversations/{id}/runs` | Yes | Start a new run with user message |
| GET | `/api/runs/{id}` | Yes | Get run status & result |
| GET | `/api/runs/{id}/events` | Yes | SSE stream of run events |
| POST | `/api/runs/{id}/stop` | Yes | Request cancellation |

### 2.4 Approvals

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/approvals` | Yes | List pending approvals |
| GET | `/api/approvals/{id}` | Yes | Get approval details |
| POST | `/api/approvals/{id}/approve` | Yes | Approve the operation |
| POST | `/api/approvals/{id}/deny` | Yes | Deny the operation |

### 2.5 Knowledge Library

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| GET | `/api/knowledge` | Yes | List items (filter: type, tags, query) |
| POST | `/api/knowledge` | Yes | Create item |
| GET | `/api/knowledge/{id}` | Yes | Get item |
| PATCH | `/api/knowledge/{id}` | Yes | Update item |
| DELETE | `/api/knowledge/{id}` | Yes | Delete item |

## 3. Request/Response Schemas

### 3.1 Auth

**POST /api/auth/login**
```json
// Request
{ "email": "user@example.com", "password": "string" }

// Response 200
{ "token": "string", "expires_at": "2026-10-23T10:00:00Z", "user": { "id": "usr_...", "email": "..." } }
```

**POST /api/auth/logout** → `204 No Content`

### 3.2 Conversations

**GET /api/conversations** → `200`
```json
{
  "items": [
    { "id": "conv_...", "title": "string", "created_at": "ISO8601", "updated_at": "ISO8601", "message_count": 5, "hermes_session_id": "ses_..." }
  ],
  "total": 42,
  "page": 1,
  "page_size": 20
}
```

**POST /api/conversations**
```json
// Request
{ "title": "Optional title", "initial_message": "Optional first message" }

// Response 201
{ "id": "conv_...", "title": "...", "created_at": "...", "hermes_session_id": "ses_..." }
```

**GET /api/conversations/{id}/messages** → `200`
```json
{
  "items": [
    { "id": "msg_...", "role": "user|assistant|system|tool", "content": "string", "tool_calls": [], "tool_results": [], "created_at": "ISO8601", "run_id": "run_...|null" }
  ],
  "total": 10,
  "page": 1,
  "page_size": 50
}
```

### 3.3 Runs

**POST /api/conversations/{id}/runs**
```json
// Request
{ "message": "User message text", "stream": true }

// Response 202 (stream=true) — SSE stream follows
// Response 201 (stream=false)
{ "id": "run_...", "status": "queued", "created_at": "ISO8601" }
```

**GET /api/runs/{id}** → `200`
```json
{
  "id": "run_...",
  "conversation_id": "conv_...",
  "hermes_run_id": "run_...|null",
  "hermes_session_id": "ses_...|null",
  "status": "queued|running|waiting_approval|completed|failed|cancelled|interrupted",
  "started_at": "ISO8601",
  "completed_at": "ISO8601|null",
  "result_summary": "string|null",
  "error": "string|null",
  "events": [ { "type": "string", "data": {}, "timestamp": "ISO8601" } ]
}
```

**Run States** (local Odin states, mapped from Hermes):
- `queued` — Created, not yet sent to Hermes
- `running` — Hermes is processing
- `waiting_approval` — Hermes requested approval
- `completed` — Terminal success
- `failed` — Terminal error
- `cancelled` — User requested stop
- `interrupted` — Connection lost / backend restarted

**SSE Events (GET /api/runs/{id}/events)**
```
event: run_started
data: {"run_id": "run_...", "timestamp": "..."}

event: token
data: {"delta": "text chunk"}

event: tool_call
data: {"tool": "terminal", "args": {...}, "call_id": "..."}

event: tool_result
data: {"call_id": "...", "result": "...", "is_error": false}

event: approval_requested
data: {"approval_id": "apr_...", "operation": "terminal", "details": {...}}

event: run_completed
data: {"run_id": "run_...", "result": "final text"}

event: run_failed
data: {"run_id": "run_...", "error": "..."}

event: run_cancelled
data: {"run_id": "run_..."}
```

### 3.4 Approvals

**GET /api/approvals** → `200`
```json
{
  "items": [
    { "id": "apr_...", "run_id": "run_...", "operation": "terminal|file_write|...", "details": {}, "status": "pending|approved|denied|expired", "created_at": "ISO8601", "expires_at": "ISO8601|null" }
  ]
}
```

**POST /api/approvals/{id}/approve** → `200`
```json
{ "ok": true, "approval_id": "apr_...", "status": "approved" }
```

**POST /api/approvals/{id}/deny** → `200`
```json
{ "ok": true, "approval_id": "apr_...", "status": "denied" }
```

### 3.5 Knowledge

**GET /api/knowledge** → `200`
```json
{
  "items": [
    { "id": "knw_...", "type": "note|link|snippet|personal", "title": "...", "content": "...", "url": "string|null", "tags": ["tag1"], "created_at": "ISO8601", "updated_at": "ISO8601" }
  ],
  "total": 100,
  "page": 1,
  "page_size": 20
}
```
Query params: `type`, `tags` (comma-separated), `q` (full-text search), `page`, `page_size`

**POST /api/knowledge** → `201`
```json
// Request
{ "type": "note", "title": "My Note", "content": "Content...", "url": null, "tags": ["work"] }

// Response
{ "id": "knw_...", "type": "note", "title": "...", "content": "...", "url": null, "tags": ["work"], "created_at": "...", "updated_at": "..." }
```

**PATCH /api/knowledge/{id}** — Partial update (same fields as POST, all optional)

## 4. Authentication

- **Scheme:** Bearer token in `Authorization: Bearer <token>`
- **Token:** Opaque string, stored hashed in DB, validated on each request
- **Expiry:** Configurable (default 7 days), refresh on activity
- **CORS:** Restricted to configured origins (dev: `http://localhost:5173`, `exp://*`)

---

## 5. Error Format

All errors follow RFC 7807:
```json
{
  "type": "about:blank",
  "title": "Unauthorized",
  "status": 401,
  "detail": "Invalid or expired token",
  "instance": "/api/conversations"
}
```

Common codes:
- `400` — Validation error (details in `errors` array)
- `401` — Missing/invalid token
- `403` — Forbidden (e.g., not owner)
- `404` — Not found
- `409` — Conflict (e.g., duplicate)
- `422` — Unprocessable (semantic error)
- `500` — Internal error
- `503` — Hermes unavailable

## 6. WebSocket / SSE

### 6.1 Run Events (SSE)
- `GET /api/runs/{id}/events` — Server-Sent Events
- `Accept: text/event-stream` required
- Reconnection: Client should retry with `Last-Event-ID` header

### 6.2 Hermes PTY / Console (WebSocket)
- **Not exposed directly to clients** — Odin backend proxies
- Odin maintains WebSocket to Hermes `/api/pty` or `/api/console`
- Clients receive events via SSE above

## 7. Hermes Integration (Backend-Only)

### 7.1 Hermes Server Endpoint
- Base URL: `http://127.0.0.1:9119` (configurable via `HERMES_API_URL`)
- Auth: `X-Hermes-Session-Token` header (from `HERMES_DASHBOARD_SESSION_TOKEN` env)

### 7.2 Key Hermes Endpoints Used
| Odin Action | Hermes Endpoint |
|-------------|-----------------|
| Create chat session | `POST /api/pty` (WebSocket) or WebSocket `/api/ws` |
| Send message | WebSocket frame: `{"type": "user_message", "content": "..."}` |
| Get events | WebSocket frames from Hermes |
| Stop run | WebSocket frame: `{"type": "interrupt"}` |
| Approve | WebSocket frame: `{"type": "approval", "decision": "approve", "approval_id": "..."}` |
| Health check | `GET /api/health` |
| System status | `GET /api/status` |

### 7.3 Session Correlation
- Each Odin `conversation` → one Hermes `session_id`
- Stored in `conversations.hermes_session_id`
- Resumed on backend restart via `hermes chat --resume <session_id>`

### 7.4 Idempotency
- `POST /api/conversations/{id}/runs` accepts `Idempotency-Key` header
- Prevents duplicate runs on retry

## 8. Environment Variables (Shared)

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | Yes | SQLite: `sqlite+aiosqlite:///./odin.db` |
| `SECRET_KEY` | Yes | JWT/session signing (32+ chars) |
| `HERMES_API_URL` | Yes | `http://127.0.0.1:9119` |
| `HERMES_SESSION_TOKEN` | Yes | From `HERMES_DASHBOARD_SESSION_TOKEN` |

| `API_HOST` | No | Default `127.0.0.1` |
| `API_PORT` | No | Default `8000` |
| `LOG_LEVEL` | No | `INFO` |

**Never expose in client bundles:** `SECRET_KEY`, `HERMES_SESSION_TOKEN`, `DATABASE_URL`

## 10. Integration Rules

1. **Web & Mobile never call Hermes directly** — All traffic via Odin API
2. **Hermes credentials stay in backend** — Only Odin backend has `HERMES_SESSION_TOKEN`
3. **Odin API is the single source of truth** for conversations, knowledge, runs
4. **Hermes session persistence** — Odin maps local conversation ↔ Hermes session
5. **Streaming via SSE** — WebSocket complexity hidden in backend
6. **No mock data in production builds** — All data from live API
